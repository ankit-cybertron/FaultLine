# Frontend Running & User Guide

FaultLine features an interactive visual frontend built in [Streamlit](https://streamlit.io/) with custom [Cytoscape.js](https://js.cytoscape.org/) graph visualizations.

---

## 1. Starting the Frontend

From the repository root with the virtual environment activated:

```bash
streamlit run ui/app.py
```

The UI will automatically open in your browser at:
```
http://localhost:8501
```

---

## 2. Global Controls (Sidebar)

- **Target Tenant / Graph**: Choose between `demo_agent`, `live_chat` (interactive chat sessions), `fleet` (batch runs), `trail`, and `whowhen`.
- **Select Run / Source**:
  - **Generate fresh run**: Executes the demo agent in real-time with an optional fault override (`no_fault`, `wrong_table`, `stale_cache`, `skip_currency`, `bad_filter`, `verifier_blind`, `hallucinate_numbers`, `hallucinate_facts`).
  - **Select saved trace**: Load pre-recorded OTel traces from `data/otel/`.
  - **Upload JSON**: Upload external JSON traces.
- **Run Forensics (Origin Test)**: Triggers the root cause investigator on the active run.

---

## 3. Tab 1: Provenance Mode (Every Run)

*Purpose: "Every answer ships with the graph of what produced it."*

When an agent produces an output, this tab displays the answer alongside its verified causal provenance:

1. **Terminal Answer Card**:
   - Displays the agent's final synthesized response and token consumption.
2. **Claim Checker Card**:
   - Displays atomic claims extracted from the answer.
   - Verified claims have a green badge: `✅ Supported (Evidence: Step #1)`.
   - Unsupported or hallucinated claims have a red badge: `⚠️ Unsupported (Not found in causal graph)`.
   - Clicking "Re-verify Claims" triggers a dual-pass verification check in the background.
3. **Interactive Step Timeline**:
   - An ordered sequential timeline of every step leading to the answer.
   - Click any step to inspect its inputs, outputs, tokens, and external data sources read (`Source` nodes).
4. **Causal Graph Visualizer**:
   - Embedded Cytoscape.js canvas showing all steps and dependencies.
   - Green nodes represent clean steps; cyan nodes represent data sources; purple nodes represent verified claims.
   - Directed arrows indicate data consumption (`DEPENDS_ON`) and agent handoffs (`HANDOFF_FROM`).

---

## 4. Tab 2: Forensics Mode (Failed or Flagged Runs)

*Purpose: "Origin test: Find the earliest wrong step whose inputs are correct."*

When an agent produces an incorrect answer or crashes:

1. **Origin Test Diagnostics Card**:
   - **Root Cause Step**: Highlights the exact step index, agent name, and tool call where failure originated.
   - **Confidence Score**: Quantitative confidence metric from the investigator.
   - **Causal Path**: Breadcrumb trail of the failure cascade (e.g., `1 ➔ 2 ➔ 4 ➔ 5`).
   - **Explanation**: Plain-English explanation generated by the investigator detailing why the step failed.
2. **Shortest Causal Path in Graph**:
   - The graph visualizer highlights the causal chain in bright red/amber nodes and thick edges, muting unrelated steps.
3. **Structured Patch Viewer**:
   - Shows the minimal structured patch proposed by FaultLine (argument update, prompt revision, or configuration adjustment).
4. **Counterfactual Demonstration**:
   - **Replay Symptom Step**: Demonstrates that simply retrying or replaying the symptom step fails 100% of the time because the input data is already tainted.
   - **Replay Root Cause Step**: Restores state to the origin step, applies the proposed patch, and re-executes. The run successfully turns green.

## 5. Tab 3: Fleet Mode (Enterprise Scale)

*Purpose: "N failed runs collapse into K root causes. Fix one cause, repair the fleet."*

For production environments running thousands of agent runs daily:

1. **Fleet Summary Metrics**:
   - Total failed runs analyzed.
   - Distinct root causes identified.
   - Batch replay success rate.
2. **Cluster Breakdown by `Cause` Signature**:
   - Groups failed runs by their canonical signature (e.g., `table_mismatch:sales_q2_apac`, `regex_syntax_error`, `stale_external_rate`).
   - Shows number of impacted runs per cause and suggested fix summary.
3. **Batch Repair & Replay**:
   - Clicking **"Batch Replay Affected Runs"** executes the verified patch across all runs in that cluster and records the updated success rate.

## 6. Tab 4: Live Chat Mode (Streamed Decision Graph)

*Purpose: "Chat with a Groq LLM while a real-time graph of every observable decision is built beside the chat."*

A live dual-column interface delivering honest, transparent agent observability:

1. **Left Column: Live Chat Interface**:
   - **Groq Model Badge**: Shows the active model (e.g. `llama-3.3-70b-versatile` or `llama-3.1-8b-instant`).
   - **Prompt Suggestion Pills**: Quick 1-click test prompts (e.g. `(25 * 4) + 50`, `UTC Time`, `Causal Provenance`, `Recall Facts`).
   - **Streaming Token Response**: Assistant answers stream token by token in real time via Server-Sent Events (SSE).
   - **Chat Toolbar & Session Memory**: Reset session, switch between past conversational turns, and retain multi-turn context.
2. **Right Column: Streamed Decision Graph**:
   - **Real-Time Step Cards**: As the agent executes, decisions appear sequentially one by one (streamed) with active pulsating indicator:
     - `1. user_message (chat_input)`: Exact user query captured.
     - `2. context_selection`: Observable prompt boundary (turns kept vs dropped, character budget, policy).
     - `3. router`: The model's choice between `direct_answer` and `tool_call`, alternatives evaluated, and the machine-readable reason from JSON.
     - `4. tool_call`: Tool name and arguments without guesswork.
     - `5. tool_result`: Concrete return payload, latency, and status.
     - `6. retrieval`: Retrieved knowledge facts and historical conversation records.
     - `7. synthesis`: Input payload assembled for terminal formulation.
     - `8. chat_output`: Verified final delivery into the stream.
   - **Interactive Cytoscape.js Canvas**:
     - Visualizes the full sequential decision DAG with directed edges (`THEN`, `RETURNS`, `DELIVERS`).
     - Clicking any node directly in the Cytoscape canvas displays its real-time payload in the embedded inspection tray.
   - **Step Inspector & Pill Navigation**:
     - Clickable horizontal step pills (`#0 input`, `#1 context`, `#2 router`, `#3 tool_call`...) allow 1-click inspection.
     - Dual-tab view showing complete raw inputs and outputs as JSON.
   - **Honest Observability Guarantee**:
     - Displays an explicit disclosure badge: only observable runtime execution events are recorded. FaultLine never claims to display unobservable hidden model thoughts.

## 7. Cytoscape.js Node Styling Reference

The embedded visualizer uses an intentional, accessible color-coded scheme:

| Visual Element | Color | Semantic Meaning |
|:---|:---|:---|
| **Step (OK)** | Emerald Green (`#10b981`) | Normal step execution with valid output. |
| **Step (Root Cause)** | Crimson Red (`#ef4444`) | Earliest broken step identified by origin test. |
| **Step (In Path)** | Bright Amber (`#f59e0b`) | Downstream steps that propagated contaminated data. |
| **Source Node** | Cyan (`#06b6d4`) | Database tables, API feeds, or document sources. |
| **Claim Node (Supported)** | Soft Blue (`#3b82f6`) | Verified factual statement backed by graph evidence. |
| **Claim Node (Unsupported)** | Rose Pink (`#f43f5e`) | Hallucination or assertion unsupported by flow. |
| **Cause Node** | Violet (`#8b5cf6`) | Root cause cluster in Fleet view. |
| **Causal Path Edge** | Red thick dashed line | Active failure cascade path (`PATH_TO`). |
| **Chat Input (`user_message`)** | Royal Blue (`#1f6feb`) | User message received as initial turn input. |
| **Context Selection** | Purple (`#8957e5`) | History window budgeting & context selection boundary. |
| **Router Decision** | Amber Gold (`#d29922`) | Tool routing choice and alternative paths evaluated. |
| **Tool Call** | Warm Orange (`#e3b341`) | Invocation of registered tool with concrete arguments. |
| **Tool Result** | Forest Green (`#238636`) | Execution output returned by tool function. |
| **Retrieval** | Light Violet (`#a371f7`) | Memory / RAG search results from graph facts. |
| **Synthesis** | Azure Blue (`#388bfd`) | Assembly of final answer from tool outputs. |
| **Chat Output** | Emerald (`#2ea043`) | Final delivered turn response to user. |
